# 第05课：体验：怎么打造真正满意的用户体验

## 课程核心框架

好的用户体验不是"舒服""满意"的主观判断，而是**用户共识并实际感知到了你的解决方案**。

### 用户体验的两层含义

```
好的用户体验
│
├── 第一层：用户在选择服务时就解决方案达成共识
│     （提前共识，不是免责）
│
└── 第二层：用户感知到的产品和服务都围绕解决方案来实施
      （落地的每一个细节都在强化共识）
```

## 关键知识点详解

### KP-028：第一层含义——提前共识

解决方案不是免责声明，而是用户体验不可或缺的一部分。

**廉价航空改进前**的"免责"做法：
- "本航班不提供免费行李额度，请你慎重订票"
- 在某个环节弹出合同让人签

**改进后的"共识"做法**：
```
"感谢您选择我们航空公司。我们致力于在飞行过程中
让旅客不花没有必要的钱，所以我们把平摊到每一张
机票上的免费行李额度、免费餐食等额外服务从票价
中去掉了。如果您有需要，仍然可以在订票之后选择
增加这些服务。"
```

**效果**：用户理解了"不花不必要的钱"后，看到空乘人数少于其他航班，反而强化了共识："空乘少了几个人，这个钱也是从机票里省下来的，非常好"

### KP-029：第二层含义——每环节落地

所有可感知的细节都要围绕解决方案来实施，方案本身会让一部分体验变好的同时，**拒绝另一部分用户**。

### KP-030：用户体验地图

**定义**：从用户视角出发，用列举的方式找到用户和产品的每一个接触点，然后在每个接触点上思考如何落地解决方案、如何就方案达成共识。

**操作方法**：
1. **列出所有接触点**：从最早能接触到用户的地方开始
2. **每个接触点思考两个问题**：
   - 解决方案如何在这里落地？
   - 如何就方案与用户达成共识？

**接触点示例**（以廉价航空为例）：
```
广告 → 社交媒体 → 搜索引擎 → 订票平台 → 
邮件 → 短信 → 机场柜台 → 候机室 → 
机上座位 → 乘务员 → 飞行过程 → 行李提取
```

### KP-031：在接触点上做共识与落地

- 短信提醒：把"不花不必要的钱"作为签名放在最后
- 会员计划：给价格优惠还是额外赠送餐食？
- 每一个接触点都在共识上走了一小步
- 无数的一小步变成产品驱动增长的一大步

## 案例和例子

**廉价航空案例**：
- 解决方案：不花没有必要的钱
- 做法：取消公务舱、缩短座位间距、取消免费餐食、买同一型号飞机
- 挑战：如何让用户理解并认可这个方案？

**航空公司的用户体验地图**：
- 广告：传递"不花不必要的钱"的价值
- 订票：弹出温馨提示说明票价构成
- 短信：签名位置写上方案口号
- 机上：空乘人数少——让用户感知到"这就是省钱的体现"

## 金句摘录

> "好的用户体验不是指类似很舒服、很满意这样一种主观的判断，而是用户共识并实际感知到了你的解决方案。"

> "解决方案本身，在让一部分用户体验变好的同时，也会拒绝掉一部分用户。"

> "在每一个接触点都在共识上走了一小步，无数的一小步就变成了产品驱动增长的一大步。"

> "与用户就解决方案达成共识，目的不是为了免责或者避免投诉，而是好的用户体验中不可或缺的一部分。"

## 自检问题

**Q1**：画出你的产品的用户体验地图。你能列出从用户最早接触到最终使用之间的所有接触点吗？

<details>
<summary>答案</summary>
从用户第一次听说的渠道开始，到搜索、了解、咨询、购买、使用、售后、推荐。每个环节都列出来，越细越好。注意"最早的接触点"可能比你想象的更早——比如搜索引擎结果、朋友推荐时的描述等。
</details>

**Q2**：在你的用户体验地图上，有多少个接触点真正在传递一致的产品解决方案信息？

<details>
<summary>答案</summary>
检查每个接触点传递的信息是否与解决方案一致。你可能发现有些环节在"说一套做一套"——这就是体验裂痕。一致性越强，用户体验越好。
</details>
