## 一、NPM 简介

NPM（Node Package Manager）是 Node.js 的默认包管理工具，用于安装、共享、分发 JavaScript 包。

```bash
# 初始化和安装
npm init -y              # 快速创建 package.json
npm install <package>    # 安装包
npm i <package>          # 简写

# 卸载
npm uninstall <package>  # 卸载包
npm remove <package>     # 简写
```

## 二、package.json

`package.json` 是项目的核心配置文件，记录了项目的元数据和依赖信息。

```json
{
  "name": "02_package_demo",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "start": "node ./src/main.js",
    "build": "webpack xxx.js"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "dependencies": {
    "axios": "^0.27.2",
    "dayjs": "^1.11.3"
  },
  "devDependencies": {
    "babel": "^6.23.0",
    "webpack": "^5.73.0"
  }
}
```

### 关键字段

| 字段 | 说明 |
|------|------|
| `name` | 项目名称 |
| `version` | 项目版本号（遵循语义化版本） |
| `description` | 项目描述 |
| `main` | 入口文件路径 |
| `scripts` | 可执行的命令脚本 |
| `dependencies` | 生产环境依赖 |
| `devDependencies` | 开发环境依赖 |

## 三、依赖管理

### 3.1 dependencies vs devDependencies

```bash
# 生产依赖（项目运行时需要）
npm install axios
npm install dayjs --save
# 安装后记录到 dependencies

# 开发依赖（仅在开发时需要）
npm install webpack --save-dev
npm install babel -D
# 安装后记录到 devDependencies
```

| 依赖类型 | 说明 | 示例 |
|---------|------|------|
| `dependencies` | 生产环境需要（打包时包含） | `vue`、`axios`、`dayjs` |
| `devDependencies` | 仅开发时需要（打包时排除） | `webpack`、`babel`、`eslint` |

### 3.2 安装示例

```javascript
// 安装 dayjs 后使用
const dayjs = require('dayjs')
console.log(dayjs().format())
```

### 3.3 语义化版本控制

```
主版本号.次版本号.修订号
  ^1.11.3    → 兼容次版本更新（安装 1.x.x 最新版）
  ~1.11.3    → 兼容修订号更新（安装 1.11.x 最新版）
  1.11.3     → 锁定精确版本
  *          → 安装最新版（不推荐）
```

> [!NOTE] 版本符号说明
> `^1.11.3`：允许安装 `>=1.11.3` 且 `<2.0.0` 的版本（主版本不变）
> `~1.11.3`：允许安装 `>=1.11.3` 且 `<1.12.0` 的版本（次版本不变）
> 生产环境中建议使用 `^` 来获取安全更新，同时锁文件保证一致性。

## 四、package-lock.json

`package-lock.json` 会在 `npm install` 时自动生成，它的作用是：

1. **锁定依赖版本** —— 确保不同环境下安装的依赖版本完全一致
2. **记录依赖树** —— 记录每个包的确切版本和依赖关系
3. **加快安装速度** —— 后续 `npm install` 根据锁文件直接安装，无需重新解析依赖树

> [!WARNING] 锁文件必须提交到 Git
> `package-lock.json` 应提交到版本控制中，确保团队成员和部署环境使用完全相同的依赖版本。

## 五、npm scripts

npm scripts 是最简单的任务运行器，可以直接通过 `npm run` 执行命令。

```json
{
  "scripts": {
    "start": "node ./src/main.js",
    "build": "webpack --config wk.config.js",
    "test": "jest",
    "dev": "nodemon ./src/main.js"
  }
}
```

```bash
# 执行脚本
npm run start    # 或 npm start（start 可以省略 run）
npm run build
npm run dev

# 特殊别名
npm start        # 等同于 npm run start
npm stop         # 等同于 npm run stop
npm test         # 等同于 npm run test
```

## 六、Yarn

Yarn 是 Facebook 推出的另一个包管理工具，与 npm 兼容但有更好的性能和安全性。

```bash
# 初始化
yarn init

# 安装包
yarn add axios
yarn add webpack --dev

# 安装所有依赖
yarn install

# 卸载
yarn remove axios
```

```json
// yarn.lock —— Yarn 的锁文件
// 等价于 package-lock.json，确保依赖版本一致
```

| 对比 | npm | Yarn |
|------|-----|------|
| 初始化 | `npm init` | `yarn init` |
| 安装依赖 | `npm install` | `yarn install` |
| 添加依赖 | `npm install axios` | `yarn add axios` |
| 添加开发依赖 | `npm install webpack -D` | `yarn add webpack --dev` |
| 锁文件 | `package-lock.json` | `yarn.lock` |

## 自测问题

<details>
<summary>1. dependencies 和 devDependencies 有什么区别？</summary>

`dependencies` 是生产环境依赖，项目运行时必须的包（如 `vue`、`react`、`axios`），会打包进最终产物。`devDependencies` 是开发环境依赖，仅在开发和构建时需要（如 `webpack`、`babel`、`eslint`），不会打包进生产环境。
</details>

<details>
<summary>2. `^1.11.3` 和 `~1.11.3` 分别表示什么版本范围？</summary>

`^1.11.3` 表示允许安装 `>=1.11.3` 且 `<2.0.0` 的版本（主版本号不变）。`~1.11.3` 表示允许安装 `>=1.11.3` 且 `<1.12.0` 的版本（次版本号不变）。`^` 允许的范围更大。
</details>

<details>
<summary>3. package-lock.json 的作用是什么？应该提交到 Git 吗？</summary>

`package-lock.json` 锁定所有依赖的确切版本和依赖树结构，确保不同环境安装的版本完全一致。它应该提交到 Git 仓库中，是保证构建可重复性的关键文件。
</details>

<details>
<summary>4. npm scripts 中如何区分 package.json 中的 start 命令是否需要 npm run？</summary>

`start`、`stop`、`test` 是 npm 的内置别名，可以直接用 `npm start` 执行。其他自定义脚本（如 `build`、`dev`）必须用 `npm run script-name` 的形式执行。
</details>
