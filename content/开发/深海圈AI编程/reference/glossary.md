# 术语表

> 把技术术语翻译成"人话"。每个术语包含：**是什么**（人话解释） + **在课程哪里用到**。

---

## AI / ML 术语

| 术语 | 人话解释 | 在课程中的使用场景 |
|:----|:--------|:-----------------|
| **LLM（大语言模型）** | 用海量文本训练出来的"超级大脑"，能理解并生成人类语言。GPT、Claude、文心一言都属于 LLM。 | 整个课程的核心工具，你用 LLM（Claude）来写代码、调试、学习。 |
| **大模型** | 参数规模巨大的 AI 模型（百亿/千亿级参数），相比小模型理解能力更强、更"聪明"。 | 我们使用的 Claude、GPT-4o 都是大模型。课程中说的"用 AI"主要指用大模型。 |
| **参数** | 模型内部存储的"知识权重"，相当于大脑中神经连接的强度。参数越多，模型容量越大。 | 了解即可，不需要调参。选择模型时可以参考参数规模。 |
| **Token** | AI 的最小理解单元。1 个 Token ≈ 0.75 个中文汉字 或 0.3 个英文单词。计费和上下文都按 Token 算。 | 每次调用 Claude 都消耗 Token。大的输出/输入消耗更多 Token -> 更多费用。 |
| **上下文窗口 (Context Window)** | AI 一次能"记住"的最大信息量，超出则遗忘。Claude 的窗口约 200K Token。 | 写大项目时：文件太多会超出上下文 -> AI 开始"忘事" -> 需要 Context Engineering 解决。 |
| **幻觉 (Hallucination)** | AI 一本正经地胡说八道，编造看起来合理但实际上错误的内容。 | AI 写代码时可能编造不存在的函数名、API。需要验证和测试来发现幻觉。 |
| **Prompt** | 你发给 AI 的指令文本。好的 Prompt = 清晰的需求描述。 | 课程前期：学写 Prompt。课程后期：学写 Context（比 Prompt 更重要）。 |
| **Context Engineering** | 不是写单条指令，而是管理 AI 能看到的所有信息（文件、架构、规则）。"Prompt 工程已死，Context 工程上位"。 | [第11课：Context工程](lessons/0011-context-gong-cheng.md) 的核心内容。让 AI 写出不翻车代码的关键。 |

## Web 开发术语

| 术语 | 人话解释 | 在课程中的使用场景 |
|:----|:--------|:-----------------|
| **前端** | 用户能看到的页面部分，即"门面"。包括布局、按钮、颜色、动画等。 | [第05课](lessons/0005-qian-hou-duan-yu-next-js.md) 详细讲解。你用 Next.js 写前端页面。 |
| **后端** | 用户看不到但在服务器上运行的逻辑，即"后台"。处理数据、用户登录、支付等。 | [第05课](lessons/0005-qian-hou-duan-yu-next-js.md) 详解。Next.js API 路由就是后端。 |
| **全栈** | 能同时搞定前端和后端。Next.js 让你在一个项目里做全栈开发。 | 课程目标是让你成为"AI 驱动的全栈开发者"。 |
| **API** | "接口"——不同软件之间沟通的约定。比如前端问后端"把用户数据给我"，后端通过 API 回答。 | 你写的 `route.ts` 文件就是在定义 API。第三方服务（如 Stripe）也通过 API 对接。 |
| **REST** | 一种 API 设计风格，用 GET（获取）、POST（创建）、PUT（更新）、DELETE（删除）表示操作。 | 课程中所有 API 都遵循 REST 风格。 |
| **HTTP** | 浏览器和服务器之间通信的"语言协议"。你访问网站时浏览器就在发送 HTTP 请求。 | 理解 HTTP 请求/响应帮你调试网络问题、理解 API 调用。 |
| **JSON** | 一种轻量级数据交换格式，长得像 JavaScript 对象。API 传输数据的标准格式。 | 前端后端传输数据、配置文件、AI 返回结构化数据，都用 JSON。 |
| **域名** | 网站的"门牌号"，比如 `google.com`、`你的项目.com`。方便人记忆，替代 IP 地址。 | [第08课](lessons/0008-bu-shu-shang-xian-yu-yu-ming.md) 教你购买和绑定自定义域名。 |
| **DNS** | "门牌号查询系统"，把域名（如 `google.com`）翻译成服务器 IP 地址。 | 绑定自定义域名时，需要在 DNS 管理后台添加解析记录。 |
| **SSL** | 对网站数据进行加密，防止被窃听。启用后 URL 显示 `https://`，有小锁图标。 | Vercel 自动为你的网站启用 SSL，你不需要手动配置。 |

## 开发工具术语

| 术语 | 人话解释 | 在课程中的使用场景 |
|:----|:--------|:-----------------|
| **Git** | 代码的"版本管理工具"，记录每次修改，可以回退到任意历史版本。 | 课程中用来管理项目代码，配合 GitHub 实现代码同步和协作。 |
| **GitHub** | 基于 Git 的"代码托管平台"，类似代码版的百度网盘，存储和分享代码。 | 课程中代码都托管在 GitHub。每次改动 -> git push 到 GitHub。 |
| **IDE** | "集成开发环境"，写代码的"专业软件"。包含代码编辑器、调试器、终端等。 | Cursor ≈ AI 增强版 VS Code。TRAE = 另一个 AI IDE。 |
| **CLI** | "命令行界面"——在终端里通过输入命令来操作电脑，而不是用鼠标点击。 | `pnpm dev`、`git push`、`npx create-next-app` 都是 CLI 命令。 |
| **包管理 / 包管理器** | 帮你下载和管理别人写好的代码库（"包"），避免手动复制粘贴。 | [第10课](lessons/0010-zen-zuo-app-xiao-cheng-xu.md) 提到引入第三方库。 |
| **npm** | Node.js 的默认包管理器，Python 叫 pip，Rust 叫 cargo。 | `npm install xxx` 安装包。 |
| **pnpm** | 比 npm 更快、更省磁盘空间的包管理器（antfu 推荐使用）。 | 课程推荐使用 pnpm 替代 npm。`pnpm install` 安装依赖。 |
| **环境变量** | 存储在环境中的配置信息，如数据库密码、API Key。不在代码中硬编码。 | [第08课](lessons/0008-bu-shu-shang-xian-yu-yu-ming.md) 教你配置环境变量。敏感信息必须放环境变量。 |
| **.env** | 存储环境变量的文件，通常不提交到 Git。`.env.local` 本地开发用，`.env.production` 生产用。 | 每个项目都要创建 `.env` 存放敏感配置。 |

## 数据库术语

| 术语 | 人话解释 | 在课程中的使用场景 |
|:----|:--------|:-----------------|
| **SQL** | "结构化查询语言"——和数据库对话的语言。说 SQL = 让数据库帮你存/取数据。 | [第06课](lessons/0006-shu-ju-ku-jin-jie.md) 教你写 SQL。 |
| **NoSQL** | "非 SQL"数据库，用文档（JSON）存数据，不像关系表那样有严格的列结构。 | 本课程主要用 PostgreSQL（SQL），了解 NoSQL 的概念即可。 |
| **PostgreSQL** | 一个功能强大的开源关系型数据库，简称 PG。本课程的主力数据库。 | 所有项目的数据库都使用 PostgreSQL。部署在 Neon 上。 |
| **表** | 数据库中的"表格"，类似 Excel 的一个 sheet。每张表存一类数据（用户表、订单表）。 | 你需要为每个项目设计表结构。 |
| **行** | 表中的"一条数据"。一个用户信息存为一行。 | 新增用户 = 在 users 表中插入一行。 |
| **列** | 表中的一个"字段"。姓名、年龄、邮箱都是列。 | 设计表时先定义有哪些列。 |
| **主键 (Primary Key)** | 每一行的"身份证号"，唯一标识一条数据。通常是自增数字或用 UUID。 | 每个表都应该有主键。`id SERIAL PRIMARY KEY`。 |
| **索引** | 给数据建"目录"，加速查询。没有索引 = 从头翻到尾，有索引 = 直接翻到那一页。 | 数据量大了之后，给经常查询的列建索引。 |
| **Migration** | 数据库的"版本控制"。每次表结构变化（新增列、改类型）都记录为一个迁移文件，可以回滚。 | [第06课](lessons/0006-shu-ju-ku-jin-jie.md) 教你用 Drizzle ORM 做迁移。 |

## 部署术语

| 术语 | 人话解释 | 在课程中的使用场景 |
|:----|:--------|:-----------------|
| **部署** | 把代码"放上网"让用户能访问。开发 - 构建 - 上传服务器 - 配置域名。 | [第08课](lessons/0008-bu-shu-shang-xian-yu-yu-ming.md) 教你一键部署到 Vercel。 |
| **构建** | 把开发代码（可读，但慢）转换成生产代码（优化的，快的）。这个过程叫 build。 | `pnpm build` 执行构建。构建失败 = 部署也会失败。 |
| **打包** | 把多个文件合并、压缩成一个或少量的文件，让浏览器加载更快。 | 构建过程会自动打包，无需手动操作。 |
| **Vercel** | 专门为 Next.js 优化的部署平台，提供免费托管、自动 SSL、CDN 加速。 | 课程所有项目都部署在 Vercel。连接 GitHub 后自动部署。 |
| **Serverless** | "无服务器"——不需要自己管理服务器，平台自动按需分配资源。不用时不计费。 | Vercel 的 API 路由就是 Serverless 函数，有请求才运行。 |
| **沙箱** | 隔离的运行环境，让不信任的代码在受限环境中执行，不影响主机。 | 理解 AI 生成的代码在什么环境下执行。 |

## AI 服务术语

| 术语 | 人话解释 | 在课程中的使用场景 |
|:----|:--------|:-----------------|
| **LLM（大语言模型）** | 参见上方 AI/ML 分类。能理解生成文本的模型。 | Claude、GPT、文心一言都属于 LLM。 |
| **TTS** | "文字转语音"——让 AI 把文字读出来。Text To Speech。 | 例如 AI 朗读功能、语音助手。 |
| **ASR** | "语音转文字"——把你说的话转成文字。Automatic Speech Recognition。 | 例如语音输入、会议转录。 |
| **文生图** | AI 根据文字描述生成图片。如 DALL·E、Midjourney、Stable Diffusion。 | 产品 logo、配图、素材生成。 |
| **SDK** | "软件开发工具包"——别人封装好的工具库，让你在代码中快速调用某服务。 | 集成 Stripe 支付、Neon 数据库等都用 SDK。 |
| **API** | 参见上方 Web 分类。AI 服务通过 API 提供调用能力。 | 调用 Claude API 在你的产品中集成 AI 能力。 |
