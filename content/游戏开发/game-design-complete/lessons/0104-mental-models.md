# 第14课：玩家心智模型

## Learning Objectives

- 理解 **Mental Model (心智模型)** 的定义以及它如何决定玩家的期望与行为
- 掌握 **Design Window (设计窗口)** 四象限模型，学会用它诊断玩家体验
- 学习 **Transfer Effect (转移效应)**、**Causality (因果关系)** 和 **Stereotypes (刻板印象/期望)** 如何影响玩家的第一印象
- 学会如何通过早期原型测试扩展蓝色区域（共享理解）并管理橙色区域（创新）

## Core Idea

**Mental Model** 是玩家脑中关于"游戏应该怎么运作"的内部认知框架。当玩家的心理预期与游戏的实际设计一致时，玩家感到聪明、自信、沉浸；当两者错位时，玩家感到困惑、沮丧，甚至直接退出游戏。

课程引入了一个强有力的诊断工具——**Design Window (设计窗口)**，灵感来自高斯与洛伦兹的研究。它从"设计师意图 vs 玩家理解"两个维度，将体验分为四个区域：

```mermaid

    title Design Window - 玩家理解 vs 设计意图
    x-axis "玩家不理解" --> "玩家理解"
    y-axis "设计师未预料" --> "设计师已设计"
    quadrant-1 "蓝色区域: 共享理解<br/>玩家懂 设计师也设计了"
    quadrant-2 "红色区域: 玩家误解<br/>玩家以为有 实际没有"
    quadrant-3 "橙色区域: 设计创新<br/>设计师做了 玩家还不知道"
    quadrant-4 "绿色区域: 自发玩法<br/>玩家发现了 设计师没想到"
```

- **蓝色区域 (Shared Understanding)**：玩家的理解完全符合设计意图。例如玩家看到红色桶，用火球攻击它，桶爆炸了——体验直观流畅，玩家感到自己很聪明
- **红色区域 (Misalignment)**：玩家预期某事会发生但游戏不支持。例如玩家对红色桶施放火球，桶却不爆炸——期待落空，玩家感到困惑甚至愤怒
- **橙色区域 (Innovation)**：设计师引入的新机制。例如《死亡循环》的非线性时间循环玩法——如果玩家固守"线性任务"的旧思维模型就会迷失，需要设计师以渐进方式引导他们适应新模式
- **绿色区域 (Emergent Gameplay)**：玩家自己发现的、设计师未曾预料的策略或玩法。例如《超级马里奥64》的向后跳加速、《反恐精英》的兔子跳、《博德之门3》的桶人术

> [!TIP] Key Insight
> 优秀的游戏设计不是消除所有红色区域，而是**最大化蓝色区域**，同时以温和的方式引导橙色区域，并鼓励健康的绿色区域。玩家的心理模型需要被"教育"而不是被"强迫"——自然的教学通过视觉反馈和游戏玩法实现，而不是弹窗教程。想想你上次看到玩家认真阅读弹出教程是什么时候？大多数玩家只会疯狂按X关掉它。

## 扩展蓝色区域的方法

1. **尽早进行游戏测试**：观察新玩家接触游戏前15分钟的反应，不提供任何解释。如果玩家犹豫或困惑，说明设计不够直观
2. **竞争分析**：研究同类型中最成功的游戏，学习它们的控制方式、UI布局和系统设计。借用成功的类型惯例可以让玩家瞬间感到熟悉
3. **A/B测试与迭代设计**：制作同一设计的两个版本（例如蓝色爆炸 vs 绿色爆炸），观察玩家偏好，根据反馈进行小范围集中修改。注意不要因为个别玩家的随机抱怨而过度修正——要找多个玩家共同挣扎的共性问题

## 管理橙色区域（创新引入）的原则

- **逐渐增加的复杂性**：像《传送门》那样——先让玩家在平坦墙壁上使用传送门，再引入移动平台和复杂谜题
- **宽容的失败机制**：像《Valheim》那样——建筑因缺乏支撑而倒塌时材料全额返还，玩家通过实践而非文字学习稳定性规则
- **及时引入**：只在玩家真正需要时引入新机制——在需要二段跳才能通过的悬崖前解锁二段跳，而不是提前几小时告知

## 应对绿色区域（自发玩法）

CD Projekt Red 的做法是榜样：当发现《巫师3》玩家通过养牛卖皮刷钱时，他们没有简单地修复这个"漏洞"，而是召来一只巨大的牛群防御怪物追击玩家——将一个漏洞变成了一个有趣的社区事件。作为设计师，你应该监控速通视频、mod社区和玩家讨论，判断自发玩法是积极的创造力还是破坏体验的漏洞。

## 其他关键概念

- **Causality (因果关系)**：玩家行为与游戏结果之间的直接关联。按下攻击键 -> 出拳动画 -> 敌人后退。链条越短越直接，玩家的操控感越强
- **Transfer Effect (转移效应)**：玩家将过去的游戏经验带到新游戏中。正向转移（WASD移动、空格跳跃）使上手流畅；负向转移（同一类型中E键在不同游戏里功能不同）导致挫败
- **Stereotypes & Expectations (刻板印象与期望)**：玩家在接触游戏前就已建立的预设。绿色 = 治疗、红色 = 危险、剑 = 近战武器。满足期望让玩家自信；打破期望可以带来惊喜，但必须清晰且尽早解释

## Practice

> [!QUESTION] Self-check
> 什么是"宽容设计 (Forgiving Design)"？请举两个游戏中的例子说明它如何保护玩家的心理模型，同时促进学习和探索。

<details>
<summary>Reveal answer</summary>

宽容设计意味着**当玩家犯错时，系统不会过度惩罚**，从而鼓励尝试和探索。

例子一：《黑帝斯 (Hades)》的"惩罚契约"系统——玩家可以自主选择想要面对的难度挑战，而不是被游戏强制进入高难度。不想挑战就不选，这让玩家在舒适区内逐步提升。

例子二：《黑暗之魂》的灵魂回收机制——玩家死亡后会丢失持有的灵魂，但在死亡地点会留下一个大型灵魂球可以回去回收。从技术上讲，你并没有永久失去任何东西，只是需要再跑一趟。这种设计保留了死亡惩罚的紧张感，同时又给了玩家一个安全的"第二次机会"。

两个例子的共同点：系统**不强迫**玩家按照单一方式游戏，而是给予选择和纠错的空间，让玩家在犯错后感到"还可以再来"，而不是"我完了"。
</details>
