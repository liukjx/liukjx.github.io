# 第30课：为什么需要GDD

## Learning Objectives

- 理解游戏设计文档（**GDD**）的核心目的及其在游戏开发中的关键作用
- 掌握有效、高效、引人注目（**Effective, Efficient, Compelling**）三大文档指标
- 识别游戏设计师常用的文档类型及其适用场景
- 认识文档化的三大支柱：**决策指导、知识共享、沟通桥梁**

## Core Idea

游戏设计文档（**Game Design Document, GDD**）是每个视频游戏项目的核心与灵魂。每一位参与游戏创作的人——从艺术家到项目经理，从开发者到测试人员——都会依赖GDD来获取信息。游戏本质上是产品，而产品需要被妥善记录，否则开发团队无法对齐设计意图。

一个优秀的GDD需要满足三个关键指标：

- **Effective（有效）**：正确传达需要做的事情，尽可能减少不确定性和误解
- **Efficient（高效）**：用最精简、最直接的方式解释游戏设计
- **Compelling（引人注目）**：迎合读者需求，使用正确的形容词、图形和视觉元素补充信息

如果团队成员阅读文档后提出了反馈和问题，说明文档是成功的。相反，没有收到任何反馈的文档往往意味着没有人真正读过它。

> [!TIP] Key Insight
> 文档化的三大支柱是：**决策指导**（减少错误信息、避免寻找分散细节）、**知识共享**（让信息民主化，创造共享智慧池）、**沟通桥梁**（将团队成员通过时间和空间连接起来，确保集体愿景明确统一）。

## Worked Example

游戏设计师常见的文档类型包括：

1. **Concept Document（概念文档）**：1-2页，高度视觉化、文字极少，给出游戏想法的总体思路。适合作为第一步，帮助理清项目方向
2. **High-Level Document（高层次文档）**：约10页，创意过程真正开始的地方。描述游戏最相关的方面——剧情概述、玩法要点、技术方向，不需要详细机制或数值
3. **Mid/Low-Level Document（中层/低层文档）**：深入描述游戏机制如何运作。需要开始做出具体决策，添加艺术参考，描述角色和系统细节
4. **Game Design Document（游戏设计文档）**：完整的GDD是项目的核心参考
5. **Asset List（资产清单）**：列出游戏所需的所有资产，与制作和项目管理密切相关
6. **Scope of Work（工作范围）**：帮助组织游戏开发方式，尤其适合垂直切片或演示版本的制作

> [!IMPORTANT]
> GDD不是一本书或一本期刊，它更类似于手册。阅读文档的人必须能够理解并立即将页面上的内容付诸行动。

**文档化三大支柱详解：**

- **决策指导**：良好的文档记录为决策提供依据。当团队成员对某个系统有疑问时，文档是权威的参考来源。它减少了对个人记忆的依赖，确保即使核心成员休假或离职，项目的设计意图仍然清晰可查
- **知识共享**：知识应该属于每个人，尤其是在集体项目中。协作努力的本质在于团队的集体智慧。通过文档实现的知识共享确保了洞见、解决方案和最佳实践不局限于个体思维，而是创造一个共享智慧池
- **沟通桥梁**：最终，文档就是为了沟通。当每个人都在同一频道上，协作就变得无缝。文档起到了桥梁的作用，将团队成员通过时间和空间连接起来，确保信息流动清晰可见，集体愿景明确统一

## Triple Documentation Technique（三重文档技术）

高效的文档编写不仅仅是写文字，而是使用三种形式共同传达信息：

1. **文字描述**：长文本详细解释机制和系统
2. **图片或视频**：添加相关的多媒体参考，帮助队友理解抽象概念。一张图片如果意义明确，就值千言万语
3. **标题说明**：为每张图片或视频添加标题，提供背景信息。如果粘贴视频链接，务必从相关时刻开始播放

避免两个常见错误：只添加相关的多媒体（不相关的图像会产生反效果），不要过度添加（同一主题的5张图片不如合成1张）。

## Practice

> [!QUESTION] Self-check
> 假设你是一名刚加入中型游戏团队的设计师，团队正在开发一款3D动作冒险游戏。现有文档散落在多个文件中，缺乏统一标准。你认为应该从哪类文档开始整理？为什么？请结合本课学习的三个文档化支柱进行分析。

<details>
<summary>Reveal answer</summary>

**建议从概念文档（Concept Document）开始整理。**

原因分析：

1. **决策指导**：概念文档用1-2页纸提炼游戏的核心思想、类型、目标受众和主要机制，为团队提供一个最高层的决策锚点。团队成员可以先对齐"我们要做什么游戏"，再深入细节，避免在不清晰的大方向下做出错误决策。

2. **知识共享**：新加入的设计师通过整理概念文档，可以快速理解项目的核心愿景，并将散落在各处的创意整合为一份共享参考。这份文档让所有成员（无论何时加入）都能快速理解项目全貌。

3. **沟通桥梁**：概念文档高度视觉化、文字简洁，适合用来与新成员、管理层甚至外部合作伙伴沟通。它的易读性保证了信息传递的效率和准确性。

从概念文档入手，再逐步扩展到高层次文档、GDD和资产清单，遵循了从宏观到微观的自然设计流程，也符合文档化三大支柱的要求。
