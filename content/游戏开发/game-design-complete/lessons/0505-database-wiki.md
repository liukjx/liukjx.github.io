# 第34课：数据库与Wiki管理

## Learning Objectives

- 理解**Wiki方法**和**可视化数据库**相较于传统文字处理器的优势
- 掌握Notion数据库的创建、属性定义、视图切换和筛选排序
- 学会编写**Feature Spec（功能规格说明）** 及其详细程度要求
- 掌握Notion同步块和动态图像嵌入的使用场景

## Core Idea

对于复杂的游戏项目，**Wiki方法**和**可视化数据库**是传统文字处理器的自然演化。Wiki方法允许轻松链接不同功能并在独立文档中创建它们，支持更多布局自定义和多列展示。数据库则在过滤、排序和展示信息方面提供更强能力，有助于创建有效、高效且引人注目的文档。

**Notion数据库**的核心优势在于：
- 使用**属性（Properties）** 对信息分类，如添加Select、Multi-select、Checkbox等类型的属性
- 每个数据库行都是一个独立页面，可以在其中编写完整文档
- 可以创建多个**视图（Views）**，如表格视图、看板视图、画廊视图，并通过筛选只显示特定系统或优先级的文档
- 支持排序（如按优先级从高到低排列）和过滤（如只显示运动系统下的文档）

> [!TIP] Key Insight
> 编写Feature Spec时，应达到的详细程度是让每个参与开发该功能的团队成员（从代码、艺术、动画、UI/UX到市场营销）都能理解规范对他们的意义，以及他们将如何继续开发。**始终从提纲开始。**

## Worked Example

**Feature Spec（功能规格说明）** 在AAA开发中常用，要求以最高可能的细节水平描述某个特性：

1. **概述**：1-2段描述功能的目标，说明其影响范围
2. **详细描述**：使用子标题划分不同方面，引用参考资料（如图表、示意图）
3. **具体参数**：列出所有可能的变量，包括访问级别（代码/可编辑）、显示给玩家与否、变量类型（int/string等）
4. **极端情况**：创建情境展示功能的边界行为，使用故事板帮助理解

> [!IMPORTANT]
> Notion中的**同步块（Syncing Blocks）** 功能可以避免重复信息。如果一个信息可能在两个或更多页面上有用，复制并同步该块后，一边的更新会自动反映到另一边。这对于描述属于多个系统的机制或高度迭代的内容非常有用。

**Notion基本块及其用途：**

- **标题块**：使用Ctrl+Shift+1/2/3创建层级标题，用于文档结构
- **目录块**：自动生成标题索引，方便长文档导航
- **切换块**：折叠信息，避免信息干扰，同时保持可访问性
- **标注块**：使用独特图标强化重要信息。例如灯泡标注代表潜在想法，警告标注代表重要注意事项
- **多列布局**：通过拖拽创建列，配合全宽模式更有效地利用屏幕空间
- **块转换**：将文本转换为切换列表或页面，灵活组织内容

**动态图像嵌入：** Notion与Figma的集成使得粘贴Figma框架链接后，每次在Figma中更新内容，Notion中的预览可以通过"重新加载预览"同步更新。这消除了重复截图和粘贴的工作，确保文档始终保持最新状态。

## Practice

> [!QUESTION] Self-check
> 你正在使用Notion为一个包含"移动系统、战斗系统、经济系统"的游戏建立GDD数据库。请设计该数据库的属性结构（至少包含5个属性），并说明你会创建哪些视图来方便团队成员快速查找信息。

<details>
<summary>Reveal answer</summary>

**数据库属性设计：**

| 属性名 | 类型 | 说明 |
|--------|------|------|
| 功能名称 | Title（标题） | 功能的名称，如"角色移动" |
| 所属系统 | Multi-select | 可属于多个系统，如"移动系统"、"战斗系统" |
| 优先级 | Select | P1（最高）、P2（中）、P3（低） |
| 状态 | Select | 草稿、审核中、已完成、待更新 |
| 负责人 | Select | 负责该功能的设计师名称 |
| 是否准备好阅读 | Checkbox | 标记文档是否可供其他团队成员阅读 |
| 最后更新日期 | Date | 跟踪文档的最后更新时间 |
| 关联系统 | Relation | 关联到其他系统的数据库页面 |

**创建的视图：**

1. **全量表视图**：展示所有功能，按优先级排序，用于项目全景概览
2. **按系统筛选的看板视图**：创建"运动系统"、"战斗系统"、"经济系统"等独立看板，按状态（草稿/审核中/已完成）分组，方便各系统负责人快速查看进度
3. **画廊视图**：使用封面图片预览功能，适合向非设计团队成员展示功能概览
4. **待办视图**：筛选状态为"草稿"且优先级为"P1"的功能，集中处理最紧急的文档编写任务
5. **时间线视图**：按最后更新日期展示，帮助团队了解各功能文档的新旧程度
