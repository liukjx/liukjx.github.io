# 第35课：一页设计文档

## Learning Objectives

- 理解**One-Pager（一页设计文档）** 的用途、优势与局限性
- 掌握信息图表理论及其在一页文档中的应用方法
- 学习从宏观到微观（**Macro to Micro**）的游戏系统信息组织方法
- 学会使用**故事板（Storyboarding）** 强化系统和机制的传达

## Core Idea

One-Pager是一种强大的文档形式，不仅用于游戏设计，还用于产品设计、建筑甚至太空旅行。它是一块白色画布，可以在上面以任何方式探索和设计文档——图形、图表、地图以及任何形式的游戏系统抽象。一页文档能够以简洁且易于理解的方式传达大量数据。

**核心原则：**
1. **Self-contained（自包含）**：队友不需要其他文档就能理解和实现其中描述的功能
2. **Tell a Story（讲述故事）**：引导读者从头到尾跟随叙述。人类天生关注故事，使用"英雄之旅"结构让文档引人入胜
3. **形式自由**：可以呈现为图表、地图、方案、组件分解图等，形式不重要，重要的是传达设计

> [!TIP] Key Insight
> 创建One-Pager前必须有一份已完成的书面文档。先用纸笔勾勒草图——这允许你在低风险环境中探索不同表达方式，尝试最有效的数据呈现方法。完成草图后再寻找灵感（颜色、字体等），最后才开始制作最终版本。

## Worked Example

**从宏观到微观的信息组织方法：**

1. **列出系统和机制**：从已有文档中提取所有系统和机制的信息
2. **确定表示资产**：思考需要哪些游戏对象或资产来表示这些信息。例如，"运动系统"和"战斗系统"可能需要角色模型、敌机、生命条、子弹等
3. **从宏观到微观**：先列出所有一般要点（高层次），然后深入研究细节（低层次）
4. **留白**：一个常见错误是试图把所有内容挤在一起。大量留白的文档帮助读者获得更多视觉引导，并更加重视核心信息

**故事板技术：**
使用Figma创建类似漫画的分镜，展示特定游戏情境：
- 第一帧：展示玩家角色攻击敌人，添加简短说明
- 第二帧：展示子弹与敌人碰撞及爆炸
- 第三帧：展示结果（如"你赢了"）并解释后续操作

> [!IMPORTANT]
> 创建One-Pager的流程：**准备数据 -> 纸笔草图 -> 寻找灵感 -> 制作最终版本 -> 添加图例/参考部分 -> 获取反馈**。尽早并持续地获取反馈，重点关注"你对这个游戏有什么了解"而非"它好还是不好"。

## Practice

> [!QUESTION] Self-check
> 你为一个2D平台跳跃游戏设计了"冲刺技能"——玩家可以在空中额外冲刺一次，有冷却时间，可通过收集道具升级为二段冲刺。请按照从宏观到微观的方法，列出你在One-Pager中会呈现的信息层次，并说明你会使用什么样的视觉表达方式来传达这个机制。

<details>
<summary>Reveal answer</summary>

**信息层次（从宏观到微观）：**

1. **宏观 - 系统层**：冲刺技能属于"移动系统"，是整个移动系统的核心能力之一。在One-Pager顶部用一个大的系统关系图展示移动系统中"基础移动"、"跳跃"、"冲刺"、"攀爬"等能力的关系

2. **中观 - 机制层**：冲刺机制的核心参数——
   - 触发方式：双击跳跃键或按指定冲刺键
   - 冲刺距离：固定距离（如5个格子）
   - 冷却时间：3秒
   - 空中冲刺次数：初始1次，最多2次
   - 升级条件：收集3个冲刺升级道具

3. **微观 - 交互细节层**：
   - 冲刺时的玩家动画状态（残影效果）
   - 冲刺是否可以转向
   - 冲刺过程中是否可以攻击
   - 与敌人碰撞的处理（穿过还是造成伤害）

**视觉表达方式：**

1. **流程图**：展示玩家从"地面移动"->"跳跃"->"空中冲刺"->"落地冷却"的完整状态机流转

2. **参数表**：用简单的表格列出冲刺距离、冷却时间、冲刺次数等关键数值

3. **情境图示**：使用故事板展示三个关键场景——
   - 场景A：玩家跳跃后使用冲刺到达原本够不到的平台
   - 场景B：玩家利用冲刺穿过敌人攻击区域躲避伤害
   - 场景C：收集升级道具后从单次冲刺变为二段冲刺

4. **图标图例**：使用冲刺图标（一个向右的箭头 + 速度线）、冷却图标（沙漏）、升级图标（星星）等统一的可视符号

5. **留白**：在重要信息（如冷却时间、升级条件）周围保留足够空白，让读者第一眼就能捕捉到关键数据
