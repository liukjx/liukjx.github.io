# 游戏设计术语表

本术语表收录游戏设计学习路线中使用的核心术语。所有课程笔记和参考文档都遵循本表的术语定义。

## 核心概念

**Game Design (游戏设计)**：
创造性地为玩家设计体验的过程，通过游戏规则、机制和系统来传递情感和互动。
*避免*：只是写想法、画图

**Game (游戏)**：
一个具有规则、目标和有意义的互动的系统，玩家自愿参与并希望通过这些规则获得情感体验。
*避免*：玩具、模拟（模拟缺乏持续的玩家决策影响）

**Design (设计)**：
一种创造性的问题解决学科，以用户为中心寻找解决方案。在游戏设计中，设计师是玩家体验的首席倡导者。
*避免*：只是美术或编程工作

**Second-Order Design (二阶设计)**：
游戏设计师定义系统的规则和组件，但玩家如何驾驭这些规则则取决于玩家自己——设计的是"引擎"，体验则由玩家创造。
*避免*：一阶设计（直接设计最终结果）

## 分析框架

**MDA Framework (MDA框架)**：
由 Mechanics（机制）、Dynamics（动态）、Aesthetics（美学）组成的游戏分析框架。机制是规则，动态是机制运行时产生的行为模式，美学是玩家体验到的情感反应。
*避免*：只分析其中一个层面

**Mechanics (机制)**：
游戏的规则系统，包括玩家能做什么、不能做什么，以及游戏如何响应玩家的行为。
*避免*：和"动态"混用

**Dynamics (动态)**：
机制被玩家激活后产生的行为模式和 emergent 现象。
*避免*：和"机制"混用

**Aesthetics (美学)**：
玩家在游戏中体验到的情感反应，MDA中的"A"代表8种愉悦类型（感官、幻想、叙事、挑战、 fellowship、发现、表达、消遣）。
*避免*：仅指视觉美术

## 用户体验

**User Experience (UX / 用户体验)**：
玩家与游戏交互时的整体感受，包括可用性、认知负荷、情感反应等。
*避免*：仅指UI或界面设计

**Affordance (可供性)**：
物体或环境提供给使用者的行动可能性。在游戏中，可供性告诉玩家"这个物体可以做什么"。
*避免*：和"约束"混用

**Constraint (约束)**：
限制玩家行动的设计元素，用来引导玩家行为。约束让可供性变得清晰。
*避免*：负面意义——约束不是"限制乐趣"，而是"聚焦体验"

**Mental Model (心智模型)**：
玩家对游戏系统运作方式的内部认知模型。设计的目标是让玩家的心智模型与游戏实际运作方式对齐。
*避免*：假设玩家和设计师有相同的心智模型

**Flow (心流)**：
当挑战与技能达到平衡时，玩家进入的完全沉浸状态。心流是游戏设计追求的理想体验状态。
*避免*：把"放松"或"简单"当作心流

## 系统设计

**System (系统)**：
一组相互连接、相互作用的部分，它们作为一个整体运作并产生 emergent 行为。
*避免*：把系统等同于"很复杂"

**Feedback Loop (反馈循环)**：
系统中一个元素的变化通过一系列连接放大或抵消自身变化的循环。
*避免*：只理解正反馈（增强），忽略负反馈（平衡）

**Positive Feedback Loop (正反馈循环 / 增强循环)**：
变化被放大，导致系统朝一个方向加速发展（如领先者越领先）。
*避免*：把它等同于"好的反馈"

**Negative Feedback Loop (负反馈循环 / 平衡循环)**：
变化被抵消，系统趋向稳定或平衡（如落后玩家获得补偿机制）。
*避免*：把它等同于"坏的反馈"

**Resource (资源)**：
游戏中玩家可以获取、管理和使用的实体，可以是具体的（金币、生命值）或抽象的（时间、声誉）。
*避免*：只理解为"游戏币"

**Entity (实体)**：
游戏系统中的基本构成单元，可以是玩家、敌人、物品等所有存在于游戏世界中的"东西"。
*避免*：和"资源"混用

## 游戏化

**Gamification (游戏化)**：
在非游戏环境中使用游戏设计元素和游戏思维来提升用户参与度和动机。
*避免*：只是加积分、徽章、排行榜（PBL方法）

**Intrinsic Motivation (内在动机)**：
来自活动本身的满足感和兴趣驱动，而非外部奖励。
*避免*：和外在动机混为一谈

**Extrinsic Motivation (外在动机)**：
由外部奖励或惩罚驱动的行为动机，如分数、等级、奖品。
*避免*：作为设计的唯一依赖

## 关卡设计

**Level Design (关卡设计)**：
游戏空间的布局和编排，包括玩家路径、挑战分布、节奏控制和空间叙事。
*避免*：等同于"画地图"

**Pacing (节奏)**：
游戏中紧张与放松、挑战与休息的交替安排，控制玩家的情绪曲线。
*避免*：全程高能——没有休息的节奏会耗尽玩家

## 文档

**GDD (Game Design Document / 游戏设计文档)**：
记录游戏设计愿景、机制、系统、内容和规范的综合性文档，是团队沟通的核心工具。
*避免*：一蹴而就——GDD需要持续更新

**Game Design Manual (游戏设计手册)**：
一份精炼的、活的文档，包含游戏的核心设计原则和关键决策，比完整GDD更易于维护。
*避免*：和完整GDD混淆

**One-Page Design (一页设计文档)**：
浓缩在一页纸内的游戏核心概念文档，用于快速传达游戏创意和验证想法。
*避免*：塞入过多细节
